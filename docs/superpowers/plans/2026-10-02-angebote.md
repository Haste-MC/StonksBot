# Gegenanfragen und große Formate (Stück 5c) – Implementierungsplan

> **Für agentische Arbeiter:** ERFORDERLICHE SUB-SKILL: `superpowers:subagent-driven-development`.
> Schritte tragen Kästchen (`- [ ]`).

**Ziel:** Kontakte, die dich kennen, melden sich von sich aus – mit einem
Tausch, einem Gastpart, einem Platz als Vorgruppe, einem gemeinsamen Album,
einer Tour oder einer Einführung bei ihrem Label.

**Architektur:** Ein neues Modul `src/angebote.js`, zweigeteilt wie
`src/contacts.js` und `src/beef.js` (oben reine Rechnungen, unten Zustand),
Zahlen in `src/data/angebote.js`. Die Gegenanfrage ist der Zustellweg für
alles: Projekte und Label sind Anfragearten, keine eigenen Knöpfe.

**Spec:** `docs/superpowers/specs/2026-10-02-angebote-design.md` – sie ist die
Quelle jeder Zahl.

**Tech:** Node.js, better-sqlite3 (synchron), discord.js-Builder, eigenes
Testgerüst (`test/*.test.js`, Ausgabe „N bestanden, M fehlgeschlagen").

## Globale Vorgaben

Jede Aufgabe erbt diesen Abschnitt.

- **§3 kein Geldrucker:** kein `unb`-Aufruf in `src/angebote.js` oder
  `src/data/angebote.js`. Geld fließt ausschließlich über die vorhandenen
  Buchungen in `src/music.js`.
- **§4 faul abrechnen:** der Tageswurf und die Fristen werden beim Lesen
  gerechnet und nie allein geschrieben.
- **§6 zustandslose Knopf-IDs** `<aktion>|<arg>|<uid>`; eine alte ID wird
  höflich abgelehnt und handelt nie am falschen Objekt.
- **§7 synchron schreiben** vor dem ersten `await`. **§9 eine Buchung je
  Aktion.** **§8 späte `require`** für Modulkreise.
- **§12 Tests ohne Netz.** **§16 Fluxer: höchstens 9 Reaktionen je Nachricht,
  `overflow === undefined`.** **§17 ein Tag, eine Energie** – jede Annahme
  kostet die Stunden ihrer Art, gebucht **vor** jedem Schreiben;
  `no_time`/`exhausted` gehen unverändert durch.
- **Der Draht wird nur über `contacts.moveDraht` geschrieben.**
- **Die Musikseite kommt aus `beef.musikLage`**, nie aus `contacts.detail().seite`
  – sonst wird ein Kontakt mit Doppelrolle auf der Creator-Seite gemessen.
- **Die vier Anfragearten aus 5a bleiben vier.** `data/contacts.js REQUESTS`
  wird nicht angefasst (`test/contacts.test.js` hält das fest). Die sechs
  Gegenanfrage-Arten stehen in `src/data/angebote.js`.
- **Inhalt:** alle Texte sind Spielfiktion. Keine Aussage über Meinung,
  Charakter, Aussehen, Herkunft (außer der Staatsangehörigkeit), Familie,
  Gesundheit oder Privatleben einer realen Person; **keine Pronomen über einen
  Kontakt** (die Namen im Katalog sind echte Personen beiderlei Geschlechts).
- **Deutsch:** Oberfläche, Kommentare und Commit-Nachrichten. Letzte Zeile jeder
  Commit-Nachricht exakt `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- **Tests:** `rm -rf .testdata && DATA_DIR=.testdata node test/<x>.test.js`;
  ganze Suite `npm test 2>&1 | grep -c '❌'` → `0`. **Neue Testdateien gehören
  in das `test`-Skript in `package.json`**, sonst ist die Abnahme ohne Aussage.
  `test/storage.test.js`, `test/activities.test.js`, `test/npc.test.js`,
  `test/buyers.test.js` und gelegentlich `test/music.test.js` würfeln
  unversiegelt und fallen selten im Suite-Lauf um – vorbestehend, bei einem `❌`
  dort einmal wiederholen und es sagen.
- **Keine bestehende Erwartung abschwächen oder löschen.**

- [ ] **Schritt 3: Die reinen Rechnungen in `src/angebote.js`**

Obere Hälfte, Banner wie in `src/beef.js` („in dieser ersten Hälfte keine
Datenbank"). Vollständig:

```js
const data = require('./data/angebote');

const clamp = (lo, hi, v) => Math.max(lo, Math.min(hi, v));

/**
 * Wer meldet sich? Partner viermal so oft wie Bekannte, und wer sprachlich
 * und im Genre zu dir passt, eher – dieselbe Passung, die in 5a die
 * Antwortchance trägt.
 */
function gewichtOf({ draht, passung }) {
  if (draht < 20) return 0;
  return (draht < 50 ? data.GEWICHT_BEKANNT : data.GEWICHT_PARTNER) * passung;
}

/**
 * Das Honorar für einen Gastpart – zweiseitig gedeckelt: Es wächst mit SEINER
 * Reichweite, aber nie über ein Vielfaches dessen, was du selbst am Tag
 * verdienst. Ein Winzling wird von einem Weltstar nicht über Nacht reich.
 */
function honorarOf({ seine, tantiemenProTag }) {
  const roh = data.HONORAR_K * Math.pow(Math.max(0, seine), data.HONORAR_EXP);
  return Math.round(Math.min(roh, data.HONORAR_DECKEL_TAGE * Math.max(0, tantiemenProTag)));
}

/**
 * Die Gage als Vorgruppe: sein Publikum kommt mit, gedeckelt auf die eigene
 * Hörerschaft – dieselbe Deckelung wie beim zugesagten Konzert in 5a.
 */
function gageOf({ meine, seine, showPay, showExp }) {
  const extra = Math.min(meine, seine * data.VORGRUPPE_ANTEIL);
  return Math.round(showPay * Math.pow(meine + extra, showExp));
}

/** Wie viel Publikum ein gemeinsames Album mitbringt – höchstens das Doppelte. */
function kollaboFaktorOf({ meine, seine }) {
  return 1 + clamp(0, 1, Math.log10(1 + seine / Math.max(100, meine)) / 3);
}

/** Wann eine Anfrage verfällt. */
function fristOf(erstellt) { return erstellt + data.FRIST_TAGE * 86_400_000; }

/**
 * Wie viele Tageswürfe nachzuholen sind. Ohne die Obergrenze bekäme ein
 * Spieler nach drei Wochen Pause zwanzig Würfe auf einmal und damit sofort
 * beide Plätze voll.
 */
function rollTage(lastRoll, now) {
  if (!lastRoll) return 1;
  return clamp(0, data.ROLL_TAGE_MAX, Math.floor((now - lastRoll) / 86_400_000));
}

/** Eine Zeile im Ton des Kontakts. */
function textFor(trait, lage, name, random = Math.random) {
  const zeilen = data.LINES[trait]?.[lage] ?? [];
  if (!zeilen.length) return '';
  return zeilen[Math.min(zeilen.length - 1, Math.floor(random() * zeilen.length))]
    .replaceAll('{name}', name);
}
```

  -- offene je Konto, jede mit Frist – wer sie verstreichen lässt, zahlt mehr
  -- Draht als wer absagt.
  CREATE TABLE IF NOT EXISTS angebote (

    art        TEXT    NOT NULL,

    art           TEXT    NOT NULL,
    contact_id    TEXT    NOT NULL,

- [ ] **Schritt 3: Die Zustellung in `src/angebote.js`**

Zweites Banner („ab hier mit Datenbank"). `settle(guildId, userId, now,
random)` rechnet faul ab (§4) und gibt Ereignisse zurück, in dieser Reihenfolge:

1. **Verfallene Anfragen:** jede offene mit `frist <= now` auf `verfallen`,
   `contacts.moveDraht(..., data.DRAHT_VERFALL, now)`, `abgelehnt_folge + 1`,
   Ereignis `{ art: 'verfallen', contact, angebot }`.
2. **Verfallene Projekte:** jedes offene mit `frist <= now` auf `verfallen`,
   Ereignis `{ art: 'projekt_verfallen', … }`. Die investierten Stunden sind weg.
3. **Pause setzen:** ist `abgelehnt_folge >= data.PAUSE_SCHWELLE`, dann
   `pause_bis = now + data.PAUSE_TAGE * 86_400_000` und `abgelehnt_folge = 0`.
4. **Neue Anfragen:** nur wenn `now >= pause_bis`. `rollTage(last_roll, now)`
   Würfe; je Wurf höchstens ein Treffer (`random() < data.ANFRAGE_CHANCE`), und
   nur solange `offeneAngebote(...).length < data.ANFRAGEN_MAX`. Bei einem
   Treffer den Kontakt gewichtet ziehen (`gewichtOf` über alle Kontakte mit
   `reach`, Draht aus `db.contactsOf` über `contacts.drahtJetzt`, Passung aus
   `contacts.passungOf`), dann die **Art** gleichverteilt aus den für diesen
   Draht erlaubten ziehen, mit drei Ausnahmen: `label` nur, wenn weder ein
   Vertrag läuft (`db.activeContract`) noch ein Angebot offen ist
   (`db.openContract`); `kollabo` und `tour` nur, wenn kein Projekt offen ist;
   fällt dadurch keine Art mehr übrig, passiert bei diesem Wurf nichts.
   Ereignis `{ art: 'neu', contact, angebot, text: textFor(trait, 'anfrage', …) }`.
5. `last_roll = now`, **ein** `saveAngebotUhr`.

`settle` schreibt nur, wenn sich etwas bewegt hat.

- [ ] **Schritt 4: Annehmen und Ablehnen**

`annehmen(guildId, userId, id, now, random)` – Reihenfolge genau so:

1. `settle(...)` als Schritt 0, Ergebnis unter `vorher` mit hinausreichen
   (auch an jede Ablehnung danach – sonst verschluckt ein Klick eine verfallene
   Anfrage; genau dieser Fehler ist in 5b zweimal passiert).
2. Angebot unbekannt oder nicht `offen` → `{ ok: false, reason: 'weg', vorher }`.
3. `frist <= now` → `{ ok: false, reason: 'abgelaufen', vorher }`.
4. Kontakt nicht mehr im Katalog → `{ ok: false, reason: 'unknown', vorher }`.
5. `beef.musikLage(...)` ist `null` → `{ ok: false, reason: 'seite', vorher }`.
6. **Zeit buchen** (`creator.useTime(guildId, userId, art.time, now)`), bei

```js
function arbeiten(guildId, userId, id, now = Date.now(), random = Math.random) {
  const vorher = settle(guildId, userId, now, random);
  const p = require('./db').projektRow(guildId, id);
  if (!p || p.user_id !== String(userId) || p.status !== 'offen') {
    return { ok: false, reason: 'weg', vorher };
  }
  if (p.frist <= now) return { ok: false, reason: 'abgelaufen', vorher };

  const zeit = require('./creator').useTime(guildId, userId, data.ARBEIT_STUNDEN, now);
  if (!zeit.ok) return { ok: false, ...zeit, need: data.ARBEIT_STUNDEN, vorher };

  const ist = Math.min(p.stunden_soll, p.stunden_ist + data.ARBEIT_STUNDEN);
  if (ist < p.stunden_soll) {
    require('./db').saveProjekt(guildId, id, { stunden_ist: ist });
    return { ok: true, fertig: false, ist, soll: p.stunden_soll, zeit, vorher };
  }
  return { ok: true, fertig: true, ...abschliessen(guildId, userId, p, now, random), zeit, vorher };
}
```

`abschliessen` setzt `status = 'fertig'`, `stunden_ist = stunden_soll` und
führt das Ergebnis aus:
