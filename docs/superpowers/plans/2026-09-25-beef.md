# Beef und Disstracks (Stück 5b) – Implementierungsplan

> **Für agentische Arbeiter:** ERFORDERLICHE SUB-SKILL: `superpowers:subagent-driven-development`.
> Schritte tragen Kästchen (`- [ ]`).

**Ziel:** Musiker können andere Künstler anstacheln, Disstracks gegen sie
veröffentlichen, Gegenschläge einstecken und den Schlagabtausch gewinnen oder
verlieren – mit einer Hitze, die eskaliert und abkühlt.

**Architektur:** Neues Modul `src/beef.js`, zweigeteilt wie `src/contacts.js`
(oben reine Rechnungen ohne Datenbank und ohne Zufall, unten der Zustand),
Zahlen in `src/data/beef.js`. Der Disstrack ist eine fünfte Veröffentlichungsart
und läuft durch `music.publish`; `beef.js` dirigiert, `music.js` rechnet.

**Spec:** `docs/superpowers/specs/2026-09-25-beef-design.md` – sie ist die
Quelle jeder Zahl. Vorgänger: `docs/superpowers/specs/2026-09-25-kontakte-design.md`.

**Tech:** Node.js, better-sqlite3 (synchron), discord.js-Builder, eigenes
Testgerüst (`test/*.test.js`, Ausgabe „N bestanden, M fehlgeschlagen").

## Globale Vorgaben

Jede Aufgabe erbt diesen Abschnitt.

- **§3 kein Geldrucker:** kein `unb`-Aufruf in `src/beef.js` oder
  `src/data/beef.js`. Der Beef zahlt nur über die vorhandene
  Veröffentlichungsmaschine und über Hype (`HYPE_MAX 1,7` deckelt).
- **§4 faul abrechnen:** die Abkühlung der Hitze wird beim Lesen gerechnet und
  nie allein geschrieben; geschrieben wird sie nur, wenn ohnehin etwas anderes
  geschrieben wird.
- **§6 zustandslose Knopf-IDs** `<aktion>|<arg>|<uid>`; eine alte ID wird
  höflich abgelehnt und handelt nie am falschen Objekt.
- **§7 synchron schreiben** vor dem ersten `await`. **§9 eine Buchung je
  Aktion** – der Gegenschlag fällt genau einmal je Schlag.
- **§8 späte `require`** für Modulkreise (`beef` ↔ `contacts` ↔ `music`).
- **§12 Tests ohne Netz.** **§16 Fluxer: höchstens 9 Reaktionen je Nachricht,
  `overflow === undefined`.** **§17 ein Tag, eine Energie** – jede Beef-Aktion
  kostet 2 Stunden, gebucht auch dann, wenn sie schiefgeht.
- **Die Zeit wird vor jedem Schreiben gebucht** und `no_time`/`exhausted`
  unverändert durchgereicht.
- **Vier Anfragearten bleiben vier.** `data/contacts.js REQUESTS` wird nicht
  angefasst – `test/contacts.test.js:53` und `:179` halten das fest. Anstacheln
  und Frieden stehen in `BEEF_AKTIONEN` in `src/data/beef.js`.
- **Inhalt:** alle Texte sind Spielfiktion (Musik, Zeilen, Termine, Zahlen).
  Keine Aussage über die wirkliche Welt, keine Beleidigung, die außerhalb des
  Spiels stehen könnte, nichts über Aussehen, Herkunft, Familie oder Gesundheit
  einer Person. Ein Disstrack im Spiel prahlt über Musik und Erfolg.
- **Deutsch:** Oberfläche, Kommentare und Commit-Nachrichten. Letzte Zeile jeder
  Commit-Nachricht exakt `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- **Tests laufen so:** `rm -rf .testdata && DATA_DIR=.testdata node test/<x>.test.js`,

- [ ] **Schritt 3: Die reinen Rechnungen in `src/beef.js`**

Obere Hälfte, Banner wie in `src/contacts.js` („keine Datenbank in dieser
Hälfte"). Vollständig:

```js
const data = require('./data/beef');

const clamp = (lo, hi, v) => Math.max(lo, Math.min(hi, v));

/** Der Charakterzug beim Streit – der Geschäftsmann rechnet die Größe mit. */
function traitBonus(trait, meine, seine) {
  const basis = data.BEEF_TRAIT[trait] ?? 0;
  if (trait !== 'geschaeftlich') return basis;
  return basis + data.GESCHAEFT_GROESSE * clamp(0, 1, meine / Math.max(1, seine));
}

/**
 * Steigt er ein? Die Umkehrung der Antwortchance aus 5a: Beim Gefallen hilft
 * es, klein zu sein, beim Streit nicht. Der Riese hat nichts zu gewinnen.
 */
function einstiegOf({ meine, seine, trait }) {
  const v = Math.log10(Math.max(100, meine) / Math.max(1, seine));
  return clamp(data.EINSTIEG_MIN, data.EINSTIEG_MAX,
    data.EINSTIEG_BASIS + data.EINSTIEG_STEIGUNG * v + traitBonus(trait, meine, seine));
}

/** Wie groß der ist, den du anfasst – dieselbe Form wie staerkeOf in 5a. */
function wuchtOf({ seine, meine }) {
  return clamp(0, 1, Math.log10(1 + seine / Math.max(100, meine)) / 3);
}

/** Hip-Hop 1,0 – das Genre-Feld `risk` sagt, wie genau hingehört wird. */
function genrefaktorOf(risk) { return (risk ?? 1) / 1.3; }

/** Was ein Disstrack an Aufmerksamkeit bringt. */
function aufmerksamkeitOf({ wucht, genrefaktor, hitze }) {
  return 1 + data.DISS_AUFMERK * wucht * genrefaktor * (0.5 + 0.5 * clamp(0, 100, hitze) / 100);
}

/** Wer nach unten tritt, wird ausgelacht. */
function haemeOf({ meine, seine, genrefaktor }) {
  return clamp(0, data.HAEME_MAX,
    Math.log10(Math.max(1, meine / Math.max(1, seine))) / 3 + 0.2 * (1 - genrefaktor));
}

/** Abkühlung, faul gerechnet (§4) – schreibt nichts. */
function hitzeJetzt(row, now) {
  if (!row) return 0;
  const tage = Math.max(0, (now - (row.last_cool || 0)) / 86_400_000);
  return clamp(0, data.HITZE_MAX, row.hitze - data.HITZE_COOL_PRO_TAG * tage);
}

/** Dein Disstrack holt die Runde – außer er ging nach hinten los. */
function rundeNachDiss(haeme) { return haeme ? 'er' : 'ich'; }

/** Sein Konter holt die Runde – außer er ist so klein, dass es lächerlich wirkt. */
function rundeNachKonter(wucht) { return wucht < data.KONTER_LAECHERLICH ? 'ich' : 'er'; }

function ausgangOf(rundenIch, rundenEr) {
  if (rundenIch > rundenEr) return 'sieg';
  if (rundenIch < rundenEr) return 'niederlage';
  return 'unentschieden';
}

function bonusFaktor(status) {
  if (status === 'sieg') return data.BONUS_SIEG;
  if (status === 'niederlage') return data.BONUS_NIEDERLAGE;
  return 1;
}

/** Wer zählt dich an? Nähe im Genre, Nähe in der Größe, streitbarer Charakter. */
function anzaehlGewicht({ trait, meine, seine, gleichesGenre, verwandtesGenre }) {
  const genrenaehe = gleichesGenre ? 3 : verwandtesGenre ? 2 : 1;
  const abstand = Math.abs(Math.log10(Math.max(1, seine) / Math.max(100, meine)));
  const groessennaehe = 1 / (1 + abstand);
  return genrenaehe * groessennaehe * (1 + Math.max(0, data.BEEF_TRAIT[trait] ?? 0));
}

/** Eine Zeile im Ton des Kontakts. */
function textFor(trait, lage, name, random = Math.random) {
  const zeilen = data.LINES[trait]?.[lage] ?? [];
  if (!zeilen.length) return '';
  return zeilen[Math.min(zeilen.length - 1, Math.floor(random() * zeilen.length))]
    .replace('{name}', name);
}
```

- [ ] **Schritt 1: Tabelle in `src/db.js`**

Neben `contact_boosts` (um Zeile 1045), im selben `db.exec`-Block:

```sql
  -- Ein Beef ist ein Zustand mit eigener Uhr: die Hitze steigt mit jedem
  -- Schlag und kühlt ohne Nachschub ab. Bei 0 wird abgerechnet.
  CREATE TABLE IF NOT EXISTS beefs (
    guild_id    TEXT    NOT NULL,
    user_id     TEXT    NOT NULL,
    contact_id  TEXT    NOT NULL,
    hitze       REAL    NOT NULL DEFAULT 0,
    runden_ich  INTEGER NOT NULL DEFAULT 0,
    runden_er   INTEGER NOT NULL DEFAULT 0,
    last_hit    INTEGER NOT NULL DEFAULT 0,
    last_cool   INTEGER NOT NULL DEFAULT 0,
    konter_at   INTEGER NOT NULL DEFAULT 0,
    angefangen  INTEGER NOT NULL DEFAULT 0,
    status      TEXT    NOT NULL DEFAULT 'offen',
    bonus_until INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (guild_id, user_id, contact_id)
  );
```

- [ ] **Schritt 1: Die Messung**

Zwei Archetypen – **Musik+Creator** und **nur Musik** (der reine Creator hat
keinen Disstrack) – je zwei Varianten mit demselben gesäten Würfel: einmal wie
bisher, einmal mit Beef-Spielweise:

- anstacheln, sobald kein Beef offen ist (Ziel nach `einstiegOf × wuchtOf`, also
  der beste Kompromiss aus „steigt ein" und „ist groß genug, dass es sich lohnt")
- Disstrack, sobald ein Titel da und die Veröffentlichungssperre durch ist
- Frieden wird nicht angeboten (das ist die teure Spielweise, nicht die kluge)

10 Läufe × 365 Tage. Ausgabe: Median/Tag beider Varianten, Differenz in Prozent
(Mediane **und** je Seed gepaart), Einstiegsquote, Häme-Quote, Siegquote,
durchschnittlicher Aufmerksamkeitsfaktor, und wie viele Kanalaktionen bzw.
Veröffentlichungen die zwei Stunden gekostet haben.

**Vor jeder abgeleiteten Zahl:** die Messung gegen **einen** von Hand
gerechneten Einzelfall prüfen (ein Tag, ein Seed, eine Anfrage: Einstiegschance,
Wucht, Aufmerksamkeit von Hand nachrechnen und gegen die Ausgabe halten) und
diesen Vergleich in den Bericht schreiben. Eine stille Null ist ein Fehler, kein
Ergebnis.

**Liegt die Differenz über +25 %, wird `DISS_AUFMERK` (1,5) gesenkt und neu
gemessen** – beide Werte stehen dann im Bericht.
